# SWIR README Style Guide

A project README should help a new visitor answer five questions quickly:

1. What is this?
2. Why would I use it?
3. How do I install it?
4. How do I use it?
5. Is the project maintained and safe to try?

## Recommended order

1. Project name and one-line description
2. Main links
3. Overview
4. Highlights/features
5. Screenshots
6. Installation
7. Usage
8. Project structure or technical details
9. Roadmap
10. Contributing
11. Security
12. Search Keywords
13. Credits/maintainer

## Style

- Keep the top of the README visually clean.
- Prefer short paragraphs and meaningful headings.
- Show commands in copyable code blocks.
- Use screenshots only when they add useful context.
- Avoid huge walls of badges.
- Avoid claims that cannot be demonstrated.
- Document limitations instead of hiding them.
- Keep version-specific instructions current.

## Search Keywords

Use real phrases people might search for. Keywords should match what the project actually does.

Good examples:

`background remover`, `python desktop app`, `windows utility`, `image processing`

Avoid unrelated high-traffic keywords or repetitive keyword stuffing.

## Branding

Each user-facing SWIR application should normally have:

- its own recognizable icon,
- consistent project naming,
- screenshots matching the current release,
- a clean repository presentation,
- release notes written for users rather than only developers.
